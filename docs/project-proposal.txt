CodenamesAI: A Non-LLM Clue Generator for Codenames

Shane Lee (shane.lee@yale.edu)
Project proposal


1. INTRODUCTION

Codenames is a word-association board game. A grid of words is laid out, and one
player per team -- the spymaster -- alone knows which words belong to their team,
which to the opponent, which are neutral, and which single word is the assassin.
Each turn the spymaster says one word and one number, and their teammate guesses
which board words were meant. The clue has to signal the team's words while
signalling as little as possible toward everything else, because picking a
neutral or opponent word ends the turn and picking the assassin loses the game
outright.

The game has attracted a fair amount of work, including a recurring Codenames AI
competition built around a shared agent framework. That work divides roughly in
two. One line studies simplified abstractions of the game, replacing words with
vectors so that clue selection becomes a tractable optimization problem that can
be reasoned about cleanly. The other, more recent line hands the clue-giving
itself to a large language model and studies how well the model plays.

This project takes neither route. The aim is a model that gives clues on the real
game, with real words, without a language model producing the clue at any point.
The clue has to come from structure the system computes itself, and the interest
of the project lies in what that structure has to capture: not merely which words
are related, but how a different person will read a relation the system can only
see from its own side.


2. BACKGROUND AND RELATED WORK

Two papers are closest to this project, and they come from the same group.

Bills and Archibald, "A Deductive Agent Hierarchy: Strategic Reasoning in
Codenames" (IEEE Conference on Games, 2023), studies a simplified version of
Codenames in which the board is no longer words but high-dimensional vectors, and
the spymaster chooses a clue from some other set of vectors. Stripping out the
language reduces the game to a fairly clean optimization problem, which lets the
paper concentrate on the strategic layer -- in particular on agents that reason
using an explicit model of their teammate, arranged in a hierarchy of increasing
deductive depth. The abstraction is what makes that analysis possible, and it is
also what this project gives up by staying on the real board.

Archibald et al., "Adapting to Teammates in a Cooperative Language Game"
(arXiv:2403.00823), attacks a problem this project will run into directly.
Previous Codenames agents commit to a single internal language model, which
produces good play with teammates whose sense of word association happens to
match and worse play with everyone else. The paper presents an ensemble agent
that holds several internal experts, each with its own language model, and
learns during play which one best matches the teammate in front of it, without
prior knowledge of that teammate. It also proposes a single metric for scoring a
Codenames team, which is a harder problem than it looks.

That second paper matters here because the mismatch it identifies is exactly the
difficulty this project is organized around. A spymaster's similarity scores are
its own. The guesser has a related but different sense of which words belong
together, and every announced number is a bet on the size of that difference.


3. PROBLEM DESCRIPTION

Design a model that takes the current game state and returns a clue word together
with a clue number, intended for a human guesser.

The game state includes the board -- which words remain, and which of them belong
to the team, the opponent, the neutral pile and the assassin -- and potentially
the history of previous actions, which is relevant in Codenames in a way it is
not in many games. A clue given two turns ago whose intended words were not all
taken is still live information; so is what the opponent has revealed and how
much of the board they have left.

The output is constrained: exactly one word and one number, with the word subject
to the game's legality rules. The target is a human reader, which rules out
optimizing against any quantity that only a machine listener would track.


4. PLANNED APPROACHES

Evaluation. Models will be compared by having a Claude agent play the guesser,
on the assumption that its associations are closer to a human's than a simulated
guesser's would be. The exact metrics are not settled, but a reasonable starting
point is the average number of team words revealed per clue together with how
often a clue leads to an opponent word or the assassin. These two have to be read
together: a model that announces large numbers will score well on the first and
badly on the second, and the whole difficulty of the game lies in the trade
between them.

The first model will be a baseline that uses a single embedding space and the
current board state only. Once it plays well enough to be worth measuring
against, it will be frozen and used as the opponent for every model built
afterward. That gives a single consistent metric -- win rate against a fixed
opponent -- which is more informative than per-clue averages, since it prices
every kind of mistake at its actual cost to the game rather than counting the
mistakes separately.

From there the work splits into two directions.

The first is representational. Different embedding spaces are built from
different sources and carry different knowledge, so a clue that one space
scores highly may be invisible to another. Trying several spaces, and
potentially learning which to trust in which situation, is the natural first
extension. Deep learning methods over these representations are the obvious
follow-on once there is a training signal worth fitting.

The second is strategic, and concerns what the current board state leaves out.
One idea is to use Monte Carlo simulation to look ahead: rolling out plausible
continuations, including the opponent's likely actions, and choosing the clue
that leads to the better distribution of future positions rather than the one
that scores best this turn. This matters most when the team's remaining words
are entangled with the opponent's, where a clue that reveals two words now may
hand over a much easier board.

A second idea uses clue history. If a clue is given and the teammate misses one
of the intended words, that word is usually still understood -- the teammate will
often take it on a later turn once something else clarifies it. Treating such a
word as effectively revealed, rather than as a failure to be retried from
scratch, changes which clue is best next.

Beyond these, the plan is iteration: build a model, measure it against the frozen
baseline, keep what works. One constraint holds throughout. Claude's guesses are
never used as an input to any model, at training time or otherwise. The evaluation
guesser has to stay independent of everything the models are fitted on; otherwise
the models are being tuned to the specific listener they are then graded against,
and the resulting numbers would measure overfitting rather than skill.


5. DELIVERABLES

The primary deliverable is a report covering each method attempted and how it
performed, measured under the evaluation described above, including the ones that
did not work and why. Alongside it: the code for the full pipeline, the frozen
baseline model and every model built against it, and the recorded evaluation
results that the report's comparisons are drawn from.
