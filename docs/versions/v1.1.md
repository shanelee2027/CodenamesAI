# v1.1 — the blend guesser

## What it is

A subversion of [v1](v1.md), not a new model architecture. Same `(k,
cause)` scorer, same feature vector, same reward math
(`codenames/scorer.py`) — the only thing that changed is which guesser
pool the training data (and this checkpoint) was generated against.

v1's checkpoints are each trained against 3 separate noisy single-space
guessers (`configs/guesser_pool.json`), deliberately kept diverse in
*knowledge* per `docs/design-decisions.md`'s "diversity must be in
knowledge, not noise" principle. v1.1 instead trains against a single
guesser that blends all three spaces into one similarity score before
adding noise: `BlendGuesser(weights={glove: 0.3, numberbatch: 0.5,
wikipedia2vec: 0.2})` wrapped in `NoisyGuesser(noise_std=0.08)`
(`configs/guesser_pool_blend.json`, `codenames/guessers/blend.py`). This
is an explicit, flagged departure from that design principle — there's
only one (synthetic) listener here, not three differently-knowledgeable
ones — built as a one-off exploratory variant, not a replacement for the
standard pool.

- **Checkpoint**: `cache/blend_pool/checkpoints/scorer_best.pt`, trained
  on 200k examples generated against the blend pool. `val_loss=1.1869`,
  `val_accuracy=0.5680` after 20 epochs (not early-stopped). Not
  comparable to v1's noise-level table — different task, different
  guesser — see v1.md's note on why val_loss/val_accuracy aren't
  comparable across differently-behaved guesser pools.
- **Web UI**: auto-discovered as `learned:blend`
  (`scripts/web_inspector.py::_discover_checkpoints`, an explicit
  non-wildcard check rather than matched by the `noise_*` glob). The
  `blend` guesser itself is also injected into every noise-level pool the
  UI builds (`_pool_config_at_noise`), with its own fixed
  `noise_std=0.08` — not overridden by the play-time noise dial, since it
  wasn't trained at any of the other five noise levels.

## Self-play evaluation

Full games (`codenames/game.py::play_game`), `learned:blend` as
codemaster against its own `blend` guesser, 300 seeded boards, 300 games
(one guesser in this pool, unlike v1's 3-guesser/900-game runs). Same
`scripts/run_arena.py` setup as v1, just pointed at
`configs/guesser_pool_blend.json` and this checkpoint:

```
python scripts/run_arena.py --n-boards 300 \
    --checkpoint cache/blend_pool/checkpoints/scorer_best.pt \
    --guesser-pool-config configs/guesser_pool_blend.json
```

| codemaster | assassin-hit rate | turns (all games) | turns (wins only) |
|---|---|---|---|
| **model 1.1 (learned)** | **3.7%** | **5.28** | **5.41** |
| centroid | 8.3% | 7.38 | 7.72 |
| linear_scorer | 15.3% | 19.68 | 19.90 |
| random | 91.0% | 9.77 | 16.00 |

Per-guess role breakdown (of every individual word actually guessed,
across all 300 games per codemaster):

| codemaster | own | opponent | neutral | assassin |
|---|---|---|---|---|
| **model 1.1 (learned)** | **84.7%** | **6.5%** | **8.5%** | **0.4%** |
| centroid | 87.5% | 6.6% | 5.1% | 0.9% |
| linear_scorer | 40.1% | 31.2% | 28.0% | 0.7% |
| random | 34.7% | 31.0% | 27.3% | 7.0% |

**Not directly comparable to v1's numbers** — this is a different, easier
guesser (one blended, more-informed listener rather than 3 separate
single-space ones), so every codemaster here does better in absolute
terms than the same codemaster did against v1's standard pool (compare
`random`'s 91.0% assassin-hit rate here to 88.5% against the standard
pool — even the worst-case codemaster benefits from a smarter listener).
`centroid`'s own-word rate (87.5%) actually edges out model 1.1's here,
unlike against the standard pool — but its assassin-hit rate is still
more than double model 1.1's (8.3% vs. 3.7%), the same shape of result as
v1: comparably good at finding own words, meaningfully worse at avoiding
the one guess that ends the game. Model 1.1 turns the easier guesser into
noticeably shorter typical games (5.28 turns vs. v1's 6.46) without
trading away any of that safety margin.

Run through `codenames/gpu_arena.py`'s batched GPU path (the default as
of v1's write-up), 59.5s for all 4 codemaster x guesser pairs.

## Open questions

Same as v1's — nothing about the scorer or reward math changed here, only
the guesser it was trained/evaluated against. If a future version
compares v1 vs. v1.1 head-to-head, it needs a shared guesser pool to be a
fair comparison; the numbers above are each model against the pool it was
actually trained for, not a controlled cross-comparison.
